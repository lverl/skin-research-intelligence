## Исправление конфигурации Coolify

Лог пользователя показал остановку Compose при пустом POSTGRES_PASSWORD. Убрана зависимость от локального env_file .env, добавлены явные переменные каждого сервиса. POSTGRES_PASSWORD и APP_TOKEN обязательны; значения пользователь вводит в Coolify. Три проверки настоящим standalone Docker Compose прошли: конфигурация без локального .env, запрет пустого пароля БД, запрет пустого токена веб-доступа. Docker Engine локально не запускался; повторный деплой на сервере ещё не проверен.

При повторном прогоне пять тестов PostgreSQL получили timeout подключения к 127.0.0.1:55432 (до выполнения SQL); локальная БД сейчас недоступна. Остальные проверки и новые тесты Compose проходят. Ранее успешные пять интеграционных тестов относятся к предыдущему запуску базы, а не к текущей проверке деплоя.

По решению пользователя ручные обязательные пароли заменены генераторами Coolify SERVICE_PASSWORD_POSTGRES, SERVICE_PASSWORD_APP, SERVICE_PASSWORD_ADMIN. Их значения передаются внутренней БД и веб-приложению автоматически. Внешние API-ключи остаются пользовательскими. Четыре проверки настоящего Compose прошли, включая общий пароль БД для всех клиентов и независимость от пустых старых POSTGRES_PASSWORD/APP_TOKEN/ADMIN_TOKEN. Текущий прогон: 33 проверки выполнены успешно, 5 интеграционных PostgreSQL пропущены; реальный повторный деплой требует проверки в Coolify.

Следующий лог Coolify подтвердил PostgreSQL Healthy и запуск worker/bot, но web остановился из-за занятого порта хоста 8000. В основном Compose убрана публикация host-порта, оставлен внутренний expose 8000 для прокси Coolify. Для локального браузера добавлен необязательный docker-compose.local.yml с привязкой к 127.0.0.1 и настраиваемым LOCAL_WEB_PORT. Том базы не менялся. Шесть проверок настоящего Compose прошли; запуск исправления на сервере ещё не проверен.

## Текущий интерфейс: Telegram (2026-11-02)

По решению пользователя основной интерфейс — Telegram, без сайта и домена. Основной docker-compose.yml запускает только postgres/worker/bot; панель вынесена в необязательный docker-compose.web.yml. Бот получает вопросы через long polling, отвечает через research.answer, поддерживает /start, /help, /id, /status, /digest. Доступ по TELEGRAM_CHAT_IDS; /id раскрывает только собственный номер. Модельные ключи передаются bot для вопросов. Для подключения пользователь указывает TELEGRAM_TOKEN и разрешённые chat ID в Coolify.

Длинные ответы и выпуски разбиваются без потери текста и ссылок. Новые таблицы telegram_updates/telegram_state сохраняют offset, ответ и прогресс; digest_deliveries.next_part сохраняет части дайджеста. Повтор доставки не запускает модель заново, постоянные ошибки исключаются, временные имеют задержку и максимум пять попыток. Перед отправкой закрытого сохранённого ответа доступ проверяется снова. Возможен повтор одной части при потере сетевого подтверждения Telegram.

Проверки: 46 успешных (41 в tests/ и 5 web), 5 интеграционных PostgreSQL пропущены. Проверены 6 конфигураций Compose и 11 сценариев Telegram с подменой внешнего API. Независимое ревью и повторная проверка пройдены. Реальных сообщений, платных запросов и серверного деплоя из этой среды не выполнялось.

Текущая цель пользователя: получить первый дайджест в Telegram. Автоматический выпуск по-прежнему назначен на 19:00 Europe/Moscow; успешный деплой не отправляет выпуск немедленно. Отдельная задача collector в Coolify дала python not found; выбор контейнера по скриншоту не установлен. Расписание сбора пока не менялось: пользователь переключил приоритет на фактическую доставку. Добавлены консольные логи запуска worker/bot, прогонов сбора, наличия настроек (без значений секретов), имени бота после getMe и ошибок Telegram 401/409. Запрошена проверка /id у пользователя для разделения проблемы подключения и формирования выпуска. 11 Telegram и 9 pipeline тестов прошли. Доставка живому боту пока не подтверждена.

Скриншот пользователя подтвердил /id и доставку пустых статусов за 1–2 ноября. Живой дайджест с материалами ещё не получен. Добавлены часовая пауза неудачных источников, проверка MODEL/ключа/лимита до расходования попыток, безопасные причины HTTP и ошибок извлечения, диагностическая команда /status.
