Дата: 2026-11-09. Основание — точное «утверждаю» пользователя; неизменяемая редакция требований: [approved-spec.md](approved-spec.md), хеш/основание в [approval.json](approval.json). Активная корневая SPEC содержит те же требования с обновлённым статусом.

Реализация в `reader-relevance-20261109` от `56f9ed7`, рабочая копия Cosm2-sources-approved. Старые локальные изменения Cosm2 не переносить. A=root пишет код, B=reader_tests_b пишет тесты, C=answer_path_audit запускает проверки и выполняет read-only ревью. Файлы тестов принадлежат B, продуктовые изменения — A; C не меняет их.

1. **FIX-001:** единый JSON-профиль и чистый оценщик; запреты по предмету/применению/популяции раньше глубокого анализа. Объяснённое решение с цитатой, областью и версиями хранится аддитивно. В коллекторе предварительная оценка, тематические запросы, без платной классификации при загрузке.
2. **FIX-007:** перед глубоким разбором получать/проверять актуальный допуск. Неизвестное удерживать; первичный пересмотр внутри прежнего бюджета и cap8, исходные данные сохранять. Решения кешировать по материалу/тексту/профилю/области.
3. **FIX-009:** материал фиксирует изменения фактов и отметки тем атомарно; вопрос не вызывает общий синтез. Worker объединяет темы, сверяет входную версию до/после генерации, сохраняет повторы/паузы и не выпускает устаревший вывод.
4. **FIX-008:** выбирать факты по предмету, без служебных слов и достаточности по одному количеству; перечитывать после поиска. Проверять утверждения по отдельности, различать некорректный ответ проверяющей модели и содержательный отказ. Сохранять безопасную диагностику.
5. **DIG-002:** готовить и хранить короткую проверенную находку, общую для ленты/сводки; тематический/цитатный допуск перед публикацией, отбрасывать отдельное непригодное, сохранять полезное. Связи с фактами и их версиями обязательны.
6. **UI-001:** серверный отбор ленты, компактные карточки и раскрываемая история только во вкладке вопроса. Права сохраняются; первоначально 10/5 записей. Настоящий HTML проверяется браузером на 375 px.
7. **QA-004:** сквозной контроль на отдельной PostgreSQL и синхронизация PRD/методологии/README/канбана/progress. Завершённость локального кода отделять от живой редакционной/серверной приёмки.

Зависимости: оценка допуска → обработка/отложенный синтез → ответ/находка → серверная выдача/экран. Новых сервисов и брокера нет, модельный и Exa ledger не меняются. Сохраняются источник/цитата/тип/дата и отдельный личный допуск; версия общего допуска не выводится из личного вопроса.

C сверяет результат с БД и разрешает коммит после устранения Critical/Important. Исходный baseline: 184 passed / 0 skipped, включая 55 PG, на 56f9ed7.

Риски: слишком широкий/узкий тематический отбор; гонки версий/отзыва допуска; повторная платная генерация; старые тестовые фикстуры без нового обязательного допуска; SQL-параметры и связи JSON; приватность владельца. Положительные и отрицательные кейсы, реальные PG и read-only ревью проверяют эти риски.
