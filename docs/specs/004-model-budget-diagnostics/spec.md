# FIX-006 — объяснить блокировку бюджета модели

Дата: 2026-11-09. Статус: утверждена точным «утверждаю» пользователя 2026-11-09 после ознакомления с этой спекой.

## 1. Зачем

Владелица видит в `/status`, почему модель блокирует вызовы. Пользователь сообщил $5 фактических расходов в OpenRouter; последние логи worker показывают месячный предел $10, настройка резерва — $1. Сумма и состав внутреннего учёта пока неизвестны. Наличие зависших резервов — гипотеза, не установленная причина.

## 2. Что меняется и где

- `llm.py`: читающая сводка по тому же месячному окну и правилам, что используются при блокировке: известная стоимость, резервы вызовов с неизвестной стоимостью и их число, общая учтённая сумма, текущий лимит, резерв следующего вызова, доступный остаток и причина запрета.
- `bot/main.py`: добавить эту сводку к существующему `/status` только для `OWNER_TELEGRAM_ID`; остальные ответы и доступы сохранить. Не показывать ключи или тексты вопросов.
- Не изменять лимиты, тарифы, записи расходов, правила резервирования, расписание и источники. Не добавлять автоматический сброс или сверку с внешним API.

## 3. Как проверим

Контроль: известные расходы $5 + неизвестные резервы $5 при пределе $10 и следующем резерве $1 → остаток $0, вызов заблокирован. Без неизвестных резервов → учтено $5, остаток $5, резерв $1 допускается. Нулевая подтверждённая цена не заменяется резервом. Диагностика не выполняет SQL-запись или внешний запрос; финансовые поля не видны другим пользователям.

## 4. Одна задача с тестом

**FIX-006:** реализовать только указанную сводку; независимые тесты в `tests/test_budget.py` и `tests/test_telegram.py` проверяют цифры и доступ владельца. Перед одним коммитом `FIX-006: Explain model budget accounting in owner status` — весь набор тестов и независимая проверка по правилам репозитория. Публикация и деплой согласуются отдельно.

## 5. Открытые вопросы

Выборов для реализации нет. После получения живой сводки отдельно решаем, требуется ли сверка отдельных резервов с OpenRouter. Эта спека не разрешает уменьшать или удалять записи расходов.
